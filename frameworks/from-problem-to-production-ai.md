## A seven-stage operating framework

| Stage | Core question | Evidence of completion |
|---|---|---|
| **Discover** | Where are time, money, control or scalability being lost? | Bounded problem and baseline |
| **Design** | What rules, permissions and user decisions shape the workflow? | Workflow, controls and success measures |
| **Build** | Which components need AI, software logic or integration? | Working end-to-end prototype |
| **Test** | What happens on edge cases, ambiguity and failure? | Test cases, defects and recovery behaviour |
| **Deploy** | Can it run securely and reliably in the operating environment? | Controlled release and monitoring |
| **Adopt** | Will users trust it and fit it into their work? | Training, support and usage feedback |
| **Measure** | Did the operating outcome improve? | Outcome metrics and iteration plan |

## Three principles

### Start with the constraint

Do not begin with “Where can we use AI?” Begin with “Where are we losing time, money, control or scalability?”

### Separate interpretation from authority

LLMs are useful for unstructured interpretation and candidate actions. High-consequence execution needs deterministic controls, clear permissions and human oversight.

### Treat adoption as product work

Training, operating support and feedback are not change-management add-ons. They are part of the system design.
